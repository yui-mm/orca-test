# セットアップ・デプロイ・運用ガイド

顧客がリスキリング助成金の申請準備情報を入力し、確認用 PDF を生成する Google Apps Script Web アプリの運用手順です。申請項目の背景は [申請書類フォーマット一覧](../リスキリング助成金_申請書類フォーマット一覧.md) などの資料を参照してください。

## 配置するファイル

アプリのソースは次の3ファイルです。Google Apps Script の新しいプロジェクトを作成し、内容を対応するファイルへコピーします。

| リポジトリのファイル | Apps Script エディタで作るファイル | 用途 |
| --- | --- | --- |
| `src/Code.gs` | `Code.gs`（スクリプト） | Web アプリ入口、入力値の検証、PDF生成処理の呼び出し |
| `src/Pdf.gs` | `Pdf.gs`（スクリプト） | 一時 Docs の作成、PDF Blob の生成、Docs のゴミ箱移動 |
| `src/index.html` | `index`（HTML） | 入力画面、生成 PDF のブラウザーへの受け渡し |

HTML ファイル名は `index` とし、拡張子 `.html` はエディタ側に付けさせます。`Code.gs` が `index` を読み込むため、名前を変更しないでください。

プロジェクトは組織が管理する Google アカウントの下に作成し、所有者と保守担当者を記録します。個人アカウントだけに依存しないようにしてください。

## 必要な Google 権限

このアプリは入力内容をスプレッドシートへ保存しません。PDF 生成時に一時的な Google Docs 文書を作成し、Drive から PDF Blob を作ってブラウザーへ返した後、一時文書をゴミ箱へ移動します。生成 PDF 自体は Drive に保存せず、ブラウザーでダウンロードします。

コードが使用するサービスに対応して、Google Docs 文書の作成・編集に `DocumentApp` の権限、文書ファイルの取得・PDF 形式への変換・ゴミ箱移動に `DriveApp` の権限が必要です。Apps Script の認可画面に表示される OAuth 権限を確認してください。

デプロイ時の承認画面では、表示された Docs と Drive の権限が上記処理に対応していることを確認してください。用途が説明できない権限が表示された場合は承認せず、マニフェストや実装を確認します。実行ユーザーをデプロイ所有者にする場合、処理はそのアカウントの権限で実行されるため、所有者アカウントを適切に管理してください。

一時 Docs をゴミ箱へ移動しても、直ちに完全削除されるわけではありません。Google Drive では通常、ゴミ箱に移動したファイルは **30 日後に完全削除**されます。それまではゴミ箱から復元でき、ゴミ箱内のファイルへアクセスできる管理者や、組織の保持ポリシー・管理設定が影響する場合もあります。運用者はゴミ箱を定期的に点検し、不要な一時 Docs が残っていないことを確認してください。ブラウザーでダウンロードされた PDF は顧客側で保管されるため、保管場所や共有を顧客に案内してください。詳しくは[Google Drive ヘルプ](https://support.google.com/drive/answer/14933051?hl=ja)を参照してください。

## テスト用デプロイ

1. 本番用と分けたテスト用 Apps Script プロジェクトで作業します。
2. GAS エディタで「デプロイ」→「新しいデプロイ」→「ウェブアプリ」を選びます。
3. 実行ユーザーを選択します。運用者として実行する設定では、その運用者の権限で一時 Docs の作成や PDF 出力が行われます。
4. テスト段階のアクセス可能ユーザーは運用担当者に限定し、初回実行時に求められる権限を確認して承認します。
5. テスト用 URL から架空の入力を行い、入力チェック、日本語を含む PDF の表示・取得、失敗時の表示を確認します。実在する顧客情報は使いません。
6. 入力情報がスプレッドシートへ保存されないこと、一時 Docs が生成後にゴミ箱へ移ること、PDF が意図した取得方法・保存先になることを確認します。テストで作られた PDF やゴミ箱内の Docs は運用者が整理します。

## 公開前のアクセス制御

本番デプロイ前に、顧客が利用する範囲に合わせて「アクセスできるユーザー」を設定します。Google アカウントでのログインを必須にできる場合は、対象組織など必要最小限のユーザー範囲に限定します。外部顧客がログインなしで利用する必要がある場合、URL が転送され得ることを前提に、取得可能な PDF の扱いを確認し、入力情報や生成物が意図しない相手に共有されないようにします。

公開前チェック:

- 本番とテストのプロジェクト・URL・出力先を取り違えていない。
- 実行ユーザーが所有する Google Drive 資産へのアクセス権を確認した。
- Web アプリのアクセス範囲と、PDF の共有範囲が利用者の想定どおりである。
- URL、画面、ログ、エラー表示に入力値を不要に出していない。
- 生成 PDF が申請書そのものではなく確認用であり、公式様式・最新要件の確認が必要であることを利用者に伝えている。

## 保存・アクセス・保持の運用判断

運用開始前に、運用責任者が以下を決めて記録してください。

- **PDF の保管:** アプリは PDF を Drive に保存しない。顧客がダウンロード後に保管する場所、共有方法、社内での保管期間を案内する。
- **一時データの保持:** ゴミ箱内の一時 Docs と運用ログの点検・削除方法、担当者、確認頻度。ゴミ箱への移動は即時の完全削除を意味しない。
- **情報アクセス:** 一時 Docs を扱うデプロイ実行アカウントと、その Drive 内の閲覧権限を管理する担当者。
- **問い合わせ対応:** PDF の再取得や削除依頼、誤共有・権限設定ミスが発生した際の窓口と手順。

フォーム入力値はスプレッドシートやアプリの永続ストレージに記録されません。入力の再確認や再発行に必要な情報を後から復元できる仕組みではないため、顧客に入力内容を確認してから PDF をダウンロード・保管するよう案内してください。

## 本番公開と更新

テスト結果、アクセス範囲、実行ユーザー、保存・保持方針を記録した後、本番用プロジェクトに3ファイルを反映します。本番用 URL でデプロイし、ユーザー範囲を再確認して公開します。ソースを変更した場合は、新しいバージョンをデプロイし、テスト用 URL で再確認してから本番デプロイを更新してください。デプロイ URL、バージョン、公開日、担当者を記録します。

このアプリが生成する PDF は申請準備・社内確認用です。提出時は、管轄労働局と厚生労働省の最新様式・要件を確認してください。
